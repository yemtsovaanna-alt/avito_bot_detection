# Входные данные по задаче


# О задаче: 
Контекст. Существуют внешние сервисы, которые автоматически собирают данные из объявлений Авито: отслеживают цены, составляют сводки по категориям и выгружают контакты продавцов.
Команда Антибота подготовила выборку с разметкой на основе известных источников трафика. Положительный класс (1) представлен трафиком нескольких сервисов автоматизированного сбора данных, отрицательный (0) — трафиком, отнесенным к человеческому. 

**Твоя задача — по событиям внутри суточного окна построить модель, которая присваивает каждой cookie_id оценку от 0 до 1: чем выше значение, тем вероятнее принадлежность к положительному классу.**

**Target: 1 — трафик известных сервисов сбора данных; 0 — трафик, отнесенный к человеческому**


# Данные
Доступны файлы:

- data/train.csv — обучающая выборка с target;
- data/test.csv — тестовая выборка без target;
- data/events.csv.gz — события для построения признаков;
- sample_submission.csv — пример файла для отправки решения.

Одна строка в train.csv и test.csv соответствует одной cookie_id с заданным суточным окном наблюдения.

cookie_id — идентификатор куки, который нужно сохранить в файле с ответом.

train.csv и test.csv
В этих файлах содержатся метаданные куки и границы окна наблюдения:

cookie_id — идентификатор куки;
cookie_created_at — время первого появления куки, которое может быть раньше начала окна наблюдения;
window_start_ts — начало окна наблюдения;
window_end_ts — окончание окна наблюдения;
target — целевая переменная, есть только в train.csv.
Готовых поведенческих признаков нет — их нужно самостоятельно собрать из событий.

- events.csv.gz

events.csv.gz содержит историю событий для куки из обучающей и тестовой выборок. Одна строка соответствует одному событию.

- cookie_id — идентификатор куки;
- event_ts — время события;
- eid, event_name — код и название типа события;
- platform — платформа;
- user_agent — строка User-Agent;
- item_id, item_category, item_location, seller_type — идентификатор объявления, его категория, локация и тип продавца;
- search_query, search_page — поисковый запрос и номер страницы выдачи;
- pointer_x, pointer_y — координаты курсора в момент события.

События включают просмотры выдачи и объявлений, листание фотографий, переходы на страницу продавца, контактные действия, добавление в избранное, вход в аккаунт и показ капчи. Некоторые поля заполнены только для определенных типов событий или платформ.

# Формат решения и используемая метрика

Файл с предсказаниями должен содержать ровно две колонки:

- cookie_id — идентификатор куки из test.csv;
- score — число от 0 до 1, чем выше, тем вероятнее, что кука принадлежит боту.


Для каждой cookie_id из test.csv должна быть ровно одна строка. Пропуски, дубликаты и дополнительные куки не допускаются.

Пример формата есть в sample_submission.csv.

Основная метрика — Precision при Recall ≥ 70% на скрытой тестовой выборке. Она рассчитывается по кукам, а не по отдельным событиям.

Среди всех порогов, при которых модель находит не менее 70% ботов, выбирается порог с максимальным precision. Чем выше доля настоящих ботов среди отмеченных куки при выполнении требования по полноте, тем лучше результат.

Дополнительно могут показываться PR-AUC и ROC-AUC. Они используются для диагностики, но итоговый score на платформе считается по Precision при Recall ≥ 70%.


## Precision и Recall

Пусть:

- $y_i \in \{0, 1\}$ — целевая метка куки: $1$ для бота и $0$ в остальных случаях;
- $s_i$ — оценка модели (`score`);
- $N$ — количество куки в выборке;
- $t$ — порог классификации.

При пороге $t$ модель отмечает как ботов все куки, для которых $s_i \ge t$.

### Формулы

$$
\operatorname{Precision}(t) =
\frac{\sum_{i=1}^{N} y_i \cdot \mathbf{1}[s_i \ge t]}
{\sum_{i=1}^{N} \mathbf{1}[s_i \ge t]}
$$

$$
\operatorname{Recall}(t) =
\frac{\sum_{i=1}^{N} y_i \cdot \mathbf{1}[s_i \ge t]}
{\sum_{i=1}^{N} y_i}
$$

Здесь $\mathbf{1}[s_i \ge t]$ — индикаторная функция:

$$
\mathbf{1}[s_i \ge t] =
\begin{cases}
1, & s_i \ge t, \\
0, & s_i < t.
\end{cases}
$$

- **Precision (точность)** — доля настоящих ботов среди куки, отмеченных моделью как боты.
- **Recall (полнота)** — доля найденных ботов среди всех ботов в выборке.

## Итоговая метрика

Итоговая метрика — максимальная точность при полноте не ниже **70%**:

$$
\mathrm{P@R}_{\ge 0.7} =
\max_{t:\,\operatorname{Recall}(t) \ge 0.7}
\operatorname{Precision}(t)
$$

Куки с одинаковым значением `score` обрабатываются одной группой:
при выбранном пороге отмечаются либо все куки с таким значением, либо ни одна.

> **Отправлять порог не нужно:** проверяющая система перебирает его самостоятельно.
